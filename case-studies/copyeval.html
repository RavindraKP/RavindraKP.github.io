AI evaluation of handwritten UPSC Mains answers

A pipeline that reads a student's scanned handwritten answer, marks it the way an examiner would, and returns the original pages with margin notes, ticks and marks.

The problem

Mains preparation depends on writing answers and getting detailed feedback on them. Human evaluation of a handwritten answer copy is slow, costly and varies from one evaluator to the next.

Evaluator capacity also limited how many answers a student could submit, so the most useful practice was being rationed.

Who it serves

  • UPSC Mains aspirants writing in English or Hindi.
  • The evaluation and reviewer team, who set the marking standard and check edge cases.
  • Several product lines: assignments, essays and test series.

My role

I started at VisionIAS as a Mains copy evaluator and later reviewed other evaluators, so I wrote the marking framework from that experience. I defined the pipeline stages, set the quality bar for release and ran model selection, working with the engineering team on delivery.

How it works

  1. Scanned answer copy arrives from the admin system
  2. Pages split and handwriting read (OCR)
  3. Each sentence fact-checked
  4. Question analysed for what it demands
  5. Answer evaluated and marks awarded
  6. Comments rewritten for tone and clarity
  7. Notes, ticks and marks written onto the original pages

If more than half the text is in Devanagari, the copy switches to a Hindi set of prompts automatically.

Key decisions and trade-offs

Break one big judgement into small checked steps

Reading, fact-checking, question analysis and marking each run as a separate step with stored output. Any mark can be traced back to the step that produced it, and a weak step can be fixed without touching the rest.

Match the model to the job

A fast, low-cost model reads handwriting and checks facts; a stronger model makes the marking judgement. Models are a configuration setting, so switching provider does not need a rebuild.

Route Hindi answers to Hindi prompts

Hindi-medium students should not be judged by prompts written for English answers. Language detection after OCR decides the route.

Give feedback where students expect it

Students are used to examiner notes in the margin, so the output is the annotated original copy, not a separate report.

How quality is measured

  • Agreement with expert evaluators measured with Quadratic Weighted Kappa (QWK), which suits ordered marks: 0.77 to 0.81.
  • Human baseline scores are stored, so every new pipeline version is scored against human evaluators before release. 36 prompt versions were run this way.
  • Candidate models are compared with the live pipeline in blinded expert reviews (Model A against Model B) and dropped on statistical evidence, so model changes rest on evidence rather than vendor claims.

Outcome

  • About 97% lower evaluator cost per script and about 4-hour batch turnaround.
  • Capacity for 10,000+ scripts a day.
  • The same evaluation engine now supports several VisionIAS products.

What I would do differently

  • Run model comparisons continuously instead of as occasional projects, so upgrades do not lag behind newer models.
  • Add automatic checks for layout errors such as notes placed on the wrong page or a wrong total, because those are the first things a student notices.
  • Measure the student outcome as well as agreement: do marks improve across a student's later attempts?
